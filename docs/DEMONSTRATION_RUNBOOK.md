## 1. Executive Summary & Evaluator Talking Points

### The Core Problem
Modern scam campaigns rarely rely on a single channel. An attacker sends an SMS lure containing a disguised link, directs the victim to a credential-harvesting portal, or makes a deceptive phone call. Evaluating individual channels in isolation creates severe blind spots:
1. **Averaging Risk Down**: Simplistic fusion models average scores across channels; an attacker who pairs a legitimate site (e.g. `wikipedia.org`) with a scam message can trick an naive average into scoring "Medium" or "Safe".
2. **Hallucination in LLM Explanations**: Generic generative models invent nonexistent indicators when asked to explain fraud.

### The System's Core Innovation
1. **Heterogeneous Modality Normalization**: Converts raw outputs from diverse models (26-feature XGBoost URL classifier, TF-IDF + Naive Bayes text model, OCR visual analysis, and audio CNNs) into a unified [`ModalityResult`](file:///c:/Users/Abhishek/OneDrive/Desktop/LLM%20integration/fusion/schemas.py) contract.
2. **Defense-in-Depth Security Escalation**: If any validated detector identifies a critical threat ($\ge 0.70$ risk score with high confidence), the pipeline enforces an escalation floor—preventing high-severity threats from being diluted by benign channels.
3. **Conflict Detection**: When channels disagree (e.g. Benign URL + Malicious Text), the engine flags a `CONFLICT_WARNING`, alerting analysts to deception.
4. **Zero-Hallucination Evidence Grounding**: The explanation layer strictly cites factual evidence generated by active detectors.
5. **Experimental Boundary Governance**: Experimental or uncalibrated models (such as the ASVspoof audio model on telephony data) are flagged `is_validated = False` and mathematically excluded from final threat verdicts.

#### Understanding the Dataset-Split Differences (Evaluator Talking Point):
- **Random Split (94.44% Accuracy)**: In standard URL-level random splits, multiple URLs sharing the same root domain can appear in both training and test partitions. This allows models to memorize domain-specific token patterns, artificially inflating apparent accuracy. It is reported here solely as a baseline reference.
- **Unseen-Domain Holdout (93.94% Accuracy - Primary Generalization Benchmark)**: Grouping strictly by hostname guarantees that no domain seen during training appears in the test set (102,637 training domains vs 25,678 testing domains). This is the true metric for zero-day phishing detection.
- **External Cross-Dataset (88.48% Accuracy)**: When evaluating on an entirely separate dataset with domain overlap eliminated, performance experiences a realistic ~5.5% domain-shift penalty, demonstrating robust cross-corpus transfer without over-fitting.

### Key Technical Disclosures:
1. **Audio Models Load & Run**: Both the scam-call CNN (`audio_scam`) and ASVspoof 2019 CNN (`audio_spoof`) run live inference on 64-band log-Mel spectrograms.
2. **Domain Mismatch**: The anti-spoofing model was trained on high-fidelity anechoic studio recordings. On telephone audio, compression artifacts cause it to report false positives ($>0.99$).
3. **Safety Isolation**: Our fusion architecture isolates this: `audio_spoof` is flagged `is_validated = False`, which automatically prevents it from mathematically inflating the risk score or escalating threats.
4. **Future Work**: Full telephony deployment requires integrating a local Speech-to-Text (STT) model (such as Whisper or Vosk) to transcribe calls into text for semantic NLP analysis.
